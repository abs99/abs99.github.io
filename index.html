How I built it

The problem, the call I made, and what it did.

Workflow orchestration on Netflix Conductor#

Netflix Conductor (OSS), Apache Kafka, Spring Boot

Every change to a business workflow needed an engineer, a code change and a deploy, about three days end to end. I adopted the open-source Netflix Conductor engine and built a workflow platform on it, with Kafka events driving tasks across microservices.

Business teams now edit 200+ workflows themselves. A change that took three days ships in an hour, and engineers spend that time on new systems.

A rule execution framework on Google CEL#

Google CEL, Java, Kafka, event-driven microservices

Decision logic lived in hand-written code, so most requests fell through to a person. I built a custom rule execution framework on top of Google’s Common Expression Language: rules are written as CEL expressions and evaluated by the framework inside an event-driven decision pipeline.

It now decides 30K+ requests a day in under 2 minutes each, and manual review dropped by 60%. I designed the platform and own it in production.

Pricing API: 600 ms to 10 ms#

Java, Spring Boot, Redis, MySQL indexing

A high-traffic pricing API waited on a synchronous third-party lookup for every call, so p99 sat around 600 ms and each request carried a vendor fee. I replaced the lookup with a precomputed Redis cache and reworked the index strategy.

p99 fell to about 10 ms under 100 RPS sustained load, per-call vendor fees went away, and the service costs roughly half as much to run.

Java concurrency and async pipelines#

CompletableFuture, ExecutorService, Spring Cloud, AWS SQS and SNS

An evaluation API scored multi-part submissions one item at a time. I fanned the work out with CompletableFuture over tuned executor pools, cutting latency by 30%, and built a separate scoring microservice that saved about 1.5 seconds per request.

I then moved notifications onto an SQS and SNS pipeline so the scoring path never blocks on delivery or reporting.

An LLM in production, 120K documents a day#

Amazon Bedrock, Gemma 3 12B, OCR pipeline, Java

Document classification and extraction ran through an external vendor. I productionized Gemma 3 12B on Amazon Bedrock inside our OCR pipeline. It handles 120K documents a day, and the vendor dependency is gone.

Monolith to microservices, zero downtime#

Strangler-fig pattern, Spring Boot, Docker, Kubernetes, Jenkins

I led an 8-month strangler-fig migration of a legacy monolith into Spring Boot services. Teams now deploy independently and work in parallel, and cutover caused no production downtime. The same services power a platform for 300K active users (700K+ registered), with product and pricing logic in configuration so new products launch without rewrites.

Algorithms and automation#

Item Response Theory, Java, Hibernate, Python

I implemented 3-parameter Item Response Theory so adaptive tests pick each next question from a live estimate of the candidate’s ability. I also automated the release pipeline in Python, cutting delivery effort by 20%, and built a migration pipeline that took per-module moves from an hour to 20 minutes across 10+ products.
